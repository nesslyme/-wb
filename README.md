# Выгрузка отзывов Wildberries по артикулам (`wb_reviews.py`)

Скрипт скачивает текстовые отзывы покупателей Wildberries (Россия) по одному или
нескольким артикулам и раскладывает результат в CSV-файлы, удобные для Excel.

---

## 1. Выбранный технический подход

**Используется публичный JSON-API Wildberries, а не браузер.**

Почему так:

- Страница `/feedbacks` в браузере внутри сама обращается к тем же открытым
  JSON-эндпоинтам. Поднимать Selenium/Playwright ради этого — медленно, тяжело и
  избыточно: больше зависимостей, выше нагрузка, ниже стабильность.
- API отдаёт сразу **структурированные данные** (текст, оценка, дата, размер,
  достоинства/недостатки, артикул каждого отзыва) — ничего не нужно парсить из HTML.
- API отзывов отдаёт **весь список отзывов склейки одним ответом**, без постраничной
  подгрузки. Это позволяет получить все текстовые отзывы и затем самим отфильтровать
  их по дате (последние N дней, по умолчанию 365).

Цепочка запросов:

| Шаг | Эндпоинт | Что получаем |
|-----|----------|--------------|
| 1a | `card.wb.ru/cards/v2/detail?nm=<артикул>` | `root` (**imtId** — идентификатор склейки), бренд, название |
| 1b | `basket-XX.wbbasket.ru/.../<артикул>/info/ru/card.json` | **резерв**: `imt_id`, бренд, название — работает даже для скрытых/распроданных товаров |
| 2 | `feedbacks{1,2}.wb.ru/feedbacks/v{1,2}/<imtId>` | весь список отзывов склейки |

Данные отзывов шардированы между хостами `feedbacks1` и `feedbacks2`, поэтому скрипт
перебирает оба хоста (и версии `v1`/`v2`) и берёт первый ответ с отзывами.

**Почему два источника imtId (шаги 1a и 1b).** `card.wb.ru` отдаёт карточку только
если товар есть в поисковой выдаче. Если товар распродан/скрыт/региональный — он
вернёт пусто, и определить imtId по нему нельзя. Поэтому при неудаче скрипт
автоматически идёт на статические CDN-серверы WB (`basket-XX`), где у каждого товара
лежит `card.json` с полем `imt_id`. Это позволяет **всегда указывать только артикул**,
не передавая imtId вручную. Номер сервера (`basket-XX`) вычисляется по артикулу, а если
догадка не подошла — перебираются остальные хосты (домены `wbbasket.ru` и `wb.ru`).

> Браузерная автоматизация здесь **не требуется**. Если в будущем WB закроет API,
> код легко расширить отдельным модулем-«добытчиком» с Playwright, сохранив остальную
> логику (фильтрацию, запись CSV, сводку) без изменений.

## 3. Входные данные

Артикулы можно передавать тремя способами (можно комбинировать):

1. **Списком в командной строке:**
   ```bash
   python wb_reviews.py 491526541 494675007
   ```
2. **Через файл TXT/CSV** (`-f`):
   ```bash
   python wb_reviews.py -f articles_example.txt
   ```
   В файл можно писать артикулы по одному на строку, через запятую/пробел или
   **вставлять прямо ссылки** на карточки/отзывы — скрипт сам извлечёт артикул из
   `catalog/<артикул>` и проигнорирует `imtId`. Строки с `#` считаются комментариями.
3. **Интерактивно (минимальный UI, под Ctrl+A → Ctrl+C → Ctrl+V):**
   ```bash
   python wb_reviews.py
   ```
   Скрипт попросит вставить артикулы (можно ссылками, в любом виде) и нажать Enter
   на пустой строке.

Дополнительные параметры:

```
-o, --output  каталог, где создать папку выгрузки (по умолчанию текущий)
-d, --days    за сколько последних дней брать отзывы (по умолчанию 365)
    --delay   задержка между запросами в секундах (по умолчанию 0.7)
```

Пример:

```bash
python wb_reviews.py -f articles_example.txt -o ./exports -d 365
```

## 4. Как работает фильтрация отзывов по конкретному артикулу (склейка)

Одна карточка WB может быть «склейкой» нескольких вариантов товара, и раздел
`/feedbacks` показывает отзывы **всех** вариантов сразу. Чтобы не смешивать их:

- Запрос отзывов идёт по `imtId` (общий id склейки) — иначе данные просто не получить.
- В ответе у **каждого отзыва** есть поле `nmId` (а также дубль в `productDetails.nmId`)
  — это артикул товара, к которому относится отзыв.
- Функция `filter_reviews()` оставляет только те отзывы, у которых
  `nmId == запрошенному артикулу`. Отзывы соседних вариантов склейки отбрасываются.

Это видно в коде:

```python
def feedback_nm_id(fb):           # достаём артикул отзыва
    nm = fb.get("nmId") or (fb.get("productDetails") or {}).get("nmId")
    ...

# внутри filter_reviews():
if feedback_nm_id(fb) != nm_id:   # главный фильтр против склейки
    continue
```

Дополнительно отзыв проходит ещё два фильтра:
- **текст ≥ 2 символов** (пустые и слишком короткие отбрасываются);
- **дата ≥ (сегодня − N дней)** (по умолчанию последние 365 дней).

Фото покупателей **не скачиваются** — сохраняется только признак `Есть фото` (1/0).

## 5. Структура выходных папок

```
выгрузка отзывов ДД-ММ-ГГГГ ЧЧ-ММ/
├── сводка_выгрузки.csv            ← сопровождающий файл (см. ниже)
├── <Бренд>/
│   └── <Артикул>/
│       └── reviews.csv            ← отзывы по этому артикулу
└── Без бренда/                    ← если бренд получить не удалось
    └── <Артикул>/
        └── reviews.csv
```

Пример:

```
выгрузка отзывов 14-06-2026 18-30/Nike/491526541/reviews.csv
```

## 6. Формат CSV с отзывами

- Кодировка **UTF-8 with BOM** (корректно открывается в Excel).
- Разделитель **`;`**.
- Одна строка = один отзыв. Заголовки на русском.

Колонки (близко к скриншоту №2, с добавлением полей из ТЗ):

```
Артикул WB; Бренд; Название товара; Цвет; Размер; Дата отзыва; Оценка;
Есть фото; Текст отзыва; Достоинства; Недостатки; ID отзыва
```

«Есть фото» — флаг 1/0 (сами фото не скачиваются, как и требовалось). Если какое-то
поле недоступно в API — оно остаётся пустым, скрипт не падает.

---

## 7. Сопровождающий файл (`сводка_выгрузки.csv`)

Создаётся в корне папки выгрузки. Структура близка к скриншоту №3 и содержит по каждому
артикулу:

```
Артикул; Бренд; Название товара; Ссылка на товар; Найдено отзывов (всего);
Найдено отзывов с текстом (API); Сохранено отзывов (после фильтра);
Путь к CSV; Статус; Ошибка; Дата и время выгрузки
```

Статус принимает значения `OK`, `Нет отзывов`, `Ошибка`. В случае ошибки её текст
попадает в колонку «Ошибка», а выгрузка продолжается со следующего артикула. В конце
работы в консоль печатается **итог**: сколько успешно, сколько пусто, что не удалось.

---

## 8. Надёжность

- Сетевые ошибки и временные сбои (429/5xx) — автоматические повторы с экспоненциальной
  паузой (2, 4, 8, 16 сек), до 4 попыток.
- Если по артикулу отзывов нет или карточка недоступна — создаётся пустой/частичный
  результат, фиксируется статус, и скрипт идёт дальше.
- Между запросами выдерживается задержка (`--delay`, по умолчанию 0.7 сек), чтобы не
  создавать избыточную нагрузку на сайт.
- Ход выполнения логируется в консоль.

---

## 9. Как изменить список полей CSV

Всё управляется двумя местами в `wb_reviews.py`:

1. Список заголовков `REVIEW_COLUMNS` — порядок и названия колонок.
2. Функция `review_to_row()` — что именно кладётся в каждую колонку.

Чтобы **добавить** поле: допишите заголовок в `REVIEW_COLUMNS` и соответствующее
значение в `review_to_row()` (значения берутся из словаря отзыва `fb` или
`fb["productDetails"]`). Чтобы **убрать** — удалите строку в обоих местах.
Аналогично для сводки: `SUMMARY_COLUMNS` и формирование строки в `main()`.

## Замечание о тестировании

Логика разбора, фильтрации (включая отсев склейки), форматирования дат и записи CSV
(BOM + `;`) проверена на синтетических данных. Реальные сетевые вызовы к доменам WB
(`card.wb.ru`, `feedbacks1/2.wb.ru`) выполняются при запуске на машине с доступом в
интернет. Эндпоинты WB периодически меняются — если структура ответа поменяется,
правке подлежат функции `resolve_card()` / `fetch_feedbacks()` / `review_to_row()`.
